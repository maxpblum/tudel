# ADR 0001: Pin one Strudel version and commit its reference data

- **Status:** accepted
- **Date:** 2026-10-05
- **Workstream:** A (verification)

## Context

R-ACCURACY and R-PIN require every snippet and claim to be checked against one exact Strudel version. Strudel's authoritative function list (`doc.json`) is generated by jsdoc from the source tree and is gitignored upstream (PROPOSAL Appendix A.5). The set of sound names a learner can use depends on strudel.cc's prebake, which registers synths in code and fetches sample maps from a CDN at runtime (Appendix A.4). npm's `gitHead` for the Strudel packages is stale and doesn't identify the source commit.

## Decision

1. **One pin**, in `tools/strudel-ref/pin.json`: the Codeberg commit `f610965f` (tag `@strudel/web@1.3.0`, a descendant of `@strudel/core@1.2.6` that differs only in version bumps) plus the exact npm versions. The app and the verifier depend on exactly these npm versions.
2. **`doc.json` is committed** (`tools/strudel-ref/doc.json`), generated from a clone at the pinned commit by `generate-doc-json.sh` and normalized so it is byte-identical on every machine. `--check` regenerates and compares.
3. **`sounds.json` is committed** (`tools/strudel-ref/sounds.json`), generated by `generate-sounds.sh`. It runs the pinned superdough's own registration functions (`registerSynthSounds`, `registerZZFXSounds`, `samples`, `aliasBank`) over the sample maps listed in the pinned `website/src/repl/prebake.mjs`, plus the soundfont names from the pinned `packages/soundfonts/gm.mjs`, then reads superdough's `soundMap`. Each name is marked `synth` (offline) or `sample`/`wavetable`/`soundfont` (network).
4. The **pinned clone** (`tools/strudel-ref/.cache/strudel`, gitignored) is the source that `{cite src=...}` references point into. `pnpm strudel-ref` creates it.

## Consequences

- Gates run offline and deterministically from committed files. Only regenerating `sounds.json` needs the network.
- The CDN sample maps aren't versioned with the commit, so `sounds.json` records what they contained when generated. `generate-sounds.sh --check` (and the drift job) shows when they change.
- Bumping Strudel is one deliberate change: edit `pin.json` and `package.json` versions, regenerate both files, run `pnpm verify --update`, and review every diff (see `tools/strudel-ref/README.md`).
